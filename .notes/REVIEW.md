## The trace's light rules are its own, not the game's

- [ ] **Night-Eye's lift is a light the exposure meter takes three quarters of back**. Evidence: `apps/openmw/mwworld/player.cpp:502-503`, `apps/openmw/mwrender/renderingmanager.cpp:964-972`, `apps/openmw/mwrender/framedescriber.cpp:41-42`, `apps/openmw/mwrender/rtx/skyreader.cpp:123-126`, `:154`, `components/rtx/environment/skylight.cpp:210`, `:217`, `components/rtx/shaders/look.h:71-83`.

  In the rasterizer, Night-Eye adds `0.7 × magnitude` to the ambient term of every lit fragment. Nothing occludes it and nothing adapts it, so a cave's ambient of 0.05 becomes 0.75 at full magnitude. The ray tracer adds the same number to the room's fill (or, outdoors, to the ambient behind the sky fill). From there it is a light like any other:
  - It is occluded by `ambientReaching`.
  - The histogram meters it. In a room `mExposureBias` is pinned at one, and `EXPOSURE_ADAPTATION = 0.75` shows a frame lit `k` times brighter only `k^0.25` brighter.
  - A cave fill lifted from 0.05 to 0.75 is 133 times the linear light (decoded 0.0039 to 0.52) and shows about 3.4 times brighter, where the rasterizer's lift is the difference between black and readable.

  A Khajiit's racial power and every Night-Eye potion are therefore mostly metered away.

  Better shape: `describeWorld` already cancels the meter for `DAYLIGHT_GAIN` (`skylight.cpp:130-137`, "the day's gain is adapted to in full"). Treat the Night-Eye share the same way. Multiply `mExposureBias` by `(L_lifted / L_unlifted)^EXPOSURE_ADAPTATION`, where `L` is the light measured with and without `WorldState::mNightEye`, so the lift the effect asked for survives the adaptation. *(kind: design; severity: medium; benefit: the effect does what the game says it does)*

- [ ] **A texture in BC4, BC6H, BC7 or a float format draws grey under the ray tracer** — `components/rtx/image/texels.cpp` `readFormat`, `components/rtx/image/texturedata.hpp`, against `components/resource/imagemanager.cpp:58-68`.

## The denoisers repeat each other's per-pixel work

- [ ] **The accumulator, the glossy filter and the shadow denoiser's temporal pass each run `heldSurfaceMatches` on the same four texels with the same inputs** — `components/rtxvulkan/shaders/trace/denoise/accumulate.comp:140-152`, `components/rtxvulkan/shaders/trace/denoise/specular.comp:140-154`, `components/rtxvulkan/shaders/trace/denoise/shadowtiles.comp:314-323`, `components/rtxvulkan/trace/denoise/denoisehistory.cpp:152`, `:162`. All three build `historyFootprint(at, mCamera.mJitter, motion)` from the same `CHANNEL_MOTION` texel. All three read the same `CHANNEL_SURFACE` texel. All three load the same four texels of `mSurface.before(step)` and test them against the same normal and distance. So every pixel pays the same four 8-byte loads, the same unpack and the same tests three times, and it pays the surface and motion loads three times too. AGENTS.md says "Compute nothing twice". The better shape has two steps. First, merge the glossy filter into `accumulate.comp` behind a specialization constant for `mapped`. It has the same footprint, the same taps and the same surface history, and `DenoisePasses::record` records both in the same frame, with only the shadow denoiser between them (`components/rtxvulkan/trace/denoise/denoisepasses.cpp:67-85`). Second, have the accumulator write the four-bit match mask (or the four shares) into an `R8UI` image for `shadowtiles.comp` to read instead of `heldSurface`. *(severity: medium; benefit: one surface test per pixel instead of three, one dispatch fewer)*
- [ ] **`surfaceOut` and the pane filter's `held` are `CHANNEL_SURFACE` and `CHANNEL_PANE_SURFACE` copied into another format** — `components/rtxvulkan/shaders/trace/denoise/accumulate.comp:196`, `components/rtxvulkan/shaders/trace/denoise/pane.comp:107`, `components/rtx/shaders/accumulate.h:39`, `:79-87`. Each writes `vec4(unpackSurfaceNormal(code), distance * mDistanceScale)` as `RGBA16F` at every pixel, and each keeps a pair of images for it. The next frame reads that copy as "the surface last frame's history belongs to". That is exactly last frame's surface channel. The half-float re-encoding is also the only reason `HistoryConstants::mDistanceScale`, `DenoiseHistory::distanceScaleFor` and the `max(before, distanceScale)` floor in `heldSurfaceMatches` exist. `components/rtx/shaders/accumulate.h:15-19` defends a format of the pass's own against a channel narrowed for the trace. But a history taken from last frame's channel is narrowed exactly as this frame's is, and like is then compared with like. The better shape keeps two of each surface channel in the G-buffer, this frame's and last frame's, and binds last frame's where `mSurface.before(step)` and `mPaneHeld.before(step)` go now. That deletes the two writes (8 B/px each), the two image pairs and `mDistanceScale`. *(severity: medium; benefit: two full-frame writes and a storage scale removed, one source for "the surface")*
- [ ] **The temporal pass tests the nearest tap twice** — `components/rtxvulkan/shaders/trace/denoise/shadowtiles.comp:291-292`, `:314-319`. `nearest = before.mLow + ivec2(greaterThanEqual(before.mAcross, vec2(0.5)))` is always one of the four `historyTap(before, i)`. Its share is at least a quarter, so the loop always tests it. `sameSurface(nearest, …)` therefore reloads `heldSurface` and repeats a test whose answer the loop already holds. Run the loop first, keep its four booleans, and take the nearest corner's bit for `held`. *(severity: low; benefit: one load and one test fewer per receiver)*
- [ ] **The temporal pass reads `CHANNEL_SUNLIT` and `CHANNEL_SURFACE` at every pixel to learn what the mask pass could have packed** — `components/rtxvulkan/shaders/trace/denoise/shadowtiles.comp:131-135`, `:213`, `components/rtxvulkan/shaders/trace/denoise/shadowmask.comp:68-72`. The mask pass already loads `sunlit` at every pixel for its alpha bit. The tiles pass then loads `sunlit` and `surfaceChannel` again at every pixel only to compute `receives`, even in tiles it clears without filtering. Have the mask pass write a second word per 8×4 tile with the receiver bit. The classification then decides `gReceivers`, `allLit` and `allShadowed` from words, as its own header says it should ("reads words and not texels"), and reads texels only in tiles it filters. *(severity: low; benefit: two full-frame texel reads taken off the cleared tiles)*

## Passes run over memory or tiles that hold nothing new

- [ ] **Three independent packed fields are transformed one at a time, with a barrier after each row pass and each column pass** — `components/rtxvulkan/trace/wavepass.cpp:172-193`, `components/rtxvulkan/shaders/trace/waveline.comp:38-86`, `components/rtxvulkan/shaders/trace/waveform.comp:54-93`, `components/rtxvulkan/shaders/trace/wavecompose.comp:44-75`. Pair `p`'s passes depend only on pair `p`, yet `handOver` follows each of the six (pair, pass) dispatches. `waveform.comp` writes three complex grids, the two line passes read and write them twice, and `wavecompose.comp` reads them back. At 512² that is 6 MiB per round trip, four times a frame. The 128-grid cascade also runs `WAVE_WORKGROUP = 256` threads with only 64 working (`components/rtxvulkan/shaders/trace/waveline.comp:57`). The better shape has two dispatches and one barrier. The row pass computes the spectrum of its row for all three pairs in shared memory (what `waveform.comp` does now) and transforms them. The column pass transforms the three pairs of its column and stores straight into the two tiles with the `shift` sign (what `wavecompose.comp` does now). That deletes `waveform.comp`, `wavecompose.comp` and four barriers. *(severity: medium; benefit: about 36 MiB less traffic a frame and four queue drains fewer)*
- [ ] **`spriteruns.comp` walks every sprite for every tile, empty tiles included** — `components/rtxvulkan/shaders/scene/spriteruns.comp:67-78`, `:94-131`, `components/rtxvulkan/trace/spritepasses.cpp:70-72`. The dispatch covers every tile. A tile whose run is empty (`slot == end`, read at `:77-78`) still takes `bin.mCount / 32` strides, each with a coalesced load and a barrier, and writes nothing. Sprites cluster, so most tiles of a frame are empty, and the comment's "tiles times sprites" is paid in full. Count the non-empty tiles of the workgroup into a shared word before the first barrier, and return uniformly when it is zero. The exit is the workgroup's, so no lane waits on another. *(severity: medium; benefit: the pass scales with occupied tiles, not all tiles)*
- [ ] **Every shadow filter level reads the widest level's 16×16 square** — `components/rtxvulkan/shaders/trace/denoise/shadowfilter.comp:82-83`, `:98-115`. `APRON` is `1 << (SHADOW_FILTER_LEVELS - 1)` for every level, but `SHADOW_LEVEL` is a specialization constant and the taps reach only `1 << SHADOW_LEVEL`. - [ ] **Skinning and morphing record one dispatch per deformed mesh** — `components/rtxvulkan/shaders/scene/skin.comp:5`, `components/rtxvulkan/shaders/scene/morph.comp:5`, `components/rtxvulkan/scene/skinpass.cpp:49-116`. One dispatch over the total then finds its row by a search over the starts. Measure the command-processor cost on a crowd first. *(severity: low; benefit: hundreds of tiny dispatches become one)*
- [ ] **Two full-frame reads could ride on a neighbour pass that already reads the same pixels** — `components/rtxvulkan/shaders/display/histogram.comp:45-49` against `components/rtxvulkan/shaders/display/bloomdown.comp:29-38` (both read every pixel of `shown`); `components/rtxvulkan/shaders/trace/denoise/atrous.comp:197` against `components/rtxvulkan/shaders/trace/denoise/composite.comp:82-88` (the last level writes `ATROUS_CHANNEL` only for the composite to read it back). ## Work is batched behind a threshold, against the rule that it is incremental

- [ ] **`GrowableBuffer::outgrow` and `SlotTable::sync` remake and refill a whole table on the frame the doubling trips** — `components/rtxvulkan/device/memory/growablebuffer.hpp:38-40`, `components/rtxvulkan/device/memory/growablebuffer.cpp:19-25`, `components/rtxvulkan/device/memory/slottable.hpp:99-103`, `components/rtxvulkan/device/memory/slottable.hpp:70`. When the size passes the current capacity, `outgrow` makes a new buffer at twice the size. `SlotTable::sync` then sets `oweEverything` and writes every row of the table into that copy on that frame. `SlotTable::grow` also resizes `mRows`, a `std::vector`, on the frame path. AGENTS.md: "Work is incremental, never batched behind a threshold … a resource is appended rather than rebuilt", and "an average that hides a spike is not an answer". The callers accept the spike in so many words: `components/rtxvulkan/scene/skintables.cpp:41-43` says "a table made again is what a cell full of them costs, once per doubling" (cross-slice). The incremental shape already exists in this folder: `BlockedBuffer` (`components/rtxvulkan/device/memory/blockedbuffer.hpp:20-27`) appends a fixed block and leaves every address in place. Better: give the per-frame tables (`SlotTable` copies, the skin tables, the sprite bin) fixed-size blocks behind one address table, as the vertex and index tables have. Growth then costs one block and owes only the new rows. `GrowableBuffer` then serves only the start-up and resize paths (`components/rtxvulkan/framering.cpp:107`, `components/rtxvulkan/scene/bottomlevelstore.cpp:248`), and `outgrow` can be deleted. *(severity: medium; benefit: no frame pays for a whole table because one row crossed a power of two)*
- [ ] **A posed body is built whole only once it passes `sRebuildEvery` placements, so frames alternate between a rebuild and none** — `components/rtxvulkan/scene/sceneacceleration.cpp:174-197`, `components/rtxvulkan/scene/sceneacceleration.hpp:131-134`. `prepareRefit` rebuilds the oldest posed mesh only where `mPlacements - builtAt >= 64`. With fewer than 64 posed bodies (most interiors), most placements rebuild nothing and some rebuild one. AGENTS.md: "Work is incremental, never batched behind a threshold … not on a rota". The scratch is already sized for one rebuild every placement (`sizeRefitScratch`). The better shape: rebuild the oldest posed mesh on every placement that poses anything, with no threshold. The worst frame stays one rebuild. Every frame then costs it, and a small crowd refreshes faster. `sRebuildEvery` and the comparison go away. *(severity: low; benefit: uniform frame cost)*
