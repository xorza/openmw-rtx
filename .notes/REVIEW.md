## Memory requests leave the design's promise to the library's defaults

- [ ] **`Staging` says "host memory, write-combined" and asks only for host-visible coherent** — `components/rtxvulkan/device/memory/buffer.cpp:21-37`, `components/rtxvulkan/device/memory/buffer.hpp:40-45`, `components/rtxvulkan/device/memory/memory.cpp:50-58`, `components/rtxvulkan/device/memory/memory.cpp:158-162`, VMA `FindMemoryTypeIndex` (`build-asan/components/rtxvulkan/fetched/vma/include/vk_mem_alloc.h:14271-14326`). `askingFor` sets `requiredFlags` and nothing else, so VMA's cost is zero for the first matching type and it returns that type. `Staging` (`HOST_VISIBLE|HOST_COHERENT`) gets system write-combined memory only because NVIDIA, AMD and RADV list that type before the BAR type and the cached type. On a driver that lists `DEVICE_LOCAL|HOST_VISIBLE|HOST_COHERENT` first, every staging block lands in the BAR heap, which on a card without resizable BAR is 246 MiB that `HostWritten` tables need. The same applies to `DeviceLocal` and `mVideoType`, which take the first `DEVICE_LOCAL` type and could pick the BAR type. Better: in the `MemoryAllocator` constructor, compute one `memoryTypeBits` mask per `BufferKind` from the device's types: staging is host-visible, coherent, not device-local and not cached; device-local is device-local and not host-visible where such a type exists. Pass the mask in `VmaAllocationCreateInfo::memoryTypeBits`. Pull the choice into a pure function and test it on the RTX 2060, Ada and RADV type lists. *(severity: low; benefit: the kind's promise is stated in the request, not borrowed from driver order)*
- [ ] **The "foreign" card fixture is NVIDIA's memory layout under AMD's driver id** — `apps/components_tests/rtxvulkan/device/physicaldevice.cpp:222-228`, `components/rtxvulkan/device/memory/memory.cpp:164-186`. The case that stands for "a Radeon or an Arc" changes only `driverID`. RADV's and AMD's memory type lists, including the `DEVICE_COHERENT_AMD` types that `MemoryAllocator` must skip ("a pool asked of each stopped those cards at start-up"), appear in no fixture. The pool and video-type choice is reachable only with a live device, and no AMD device runs here. Better: add a `describeRdna2` fixture from a Vulkan Hardware Database report. Move the pool and type selection out of the `MemoryAllocator` constructor into a pure function over `VkPhysicalDeviceMemoryProperties`, and test it on the three fixtures. *(severity: low; benefit: the AMD path is held by a test on a machine with no AMD card)*

## The trace's light rules are its own, not the game's

- [ ] **Night-Eye's lift is a light the exposure meter takes three quarters of back**. Evidence: `apps/openmw/mwworld/player.cpp:502-503`, `apps/openmw/mwrender/renderingmanager.cpp:964-972`, `apps/openmw/mwrender/framedescriber.cpp:41-42`, `apps/openmw/mwrender/rtx/skyreader.cpp:123-126`, `:154`, `components/rtx/environment/skylight.cpp:210`, `:217`, `components/rtx/shaders/look.h:71-83`.

  In the rasterizer, Night-Eye adds `0.7 × magnitude` to the ambient term of every lit fragment. Nothing occludes it and nothing adapts it, so a cave's ambient of 0.05 becomes 0.75 at full magnitude. The ray tracer adds the same number to the room's fill (or, outdoors, to the ambient behind the sky fill). From there it is a light like any other:
  - It is occluded by `ambientReaching`.
  - The histogram meters it. In a room `mExposureBias` is pinned at one, and `EXPOSURE_ADAPTATION = 0.75` shows a frame lit `k` times brighter only `k^0.25` brighter.

## Shading math departs from the exact form it claims

- [ ] **The refracted ray's cone is twice too wide from above and 1.5 times too wide from below** — `components/rtxvulkan/shaders/lib/water.glsl:324`, `components/rtxvulkan/shaders/lib/water.glsl:327`, `components/rtxvulkan/shaders/lib/sea.glsl:29`, `components/rtx/shaders/brdf.h:180`. `lobe` is `ggxConeWidth(roughness², …)`. `brdf.h` defines that as the reflected cone, "twice the half vector's angle, on each side of the mirror direction": a facet tilt of θ deflects a reflection by 2θ. A refraction from air into water deflects by `(1 - 1/n)·θ`, which is `WATER_REFRACTION_BEND·θ`. So the refracted cone is `lobe · WATER_REFRACTION_BEND / 2` (×0.125), not `lobe · WATER_REFRACTION_BEND` (×0.25). From below the water the deflection is `(n - 1)·θ`, so the factor is `(WATER_IOR - 1) / 2` (×0.167), and the code still takes ×0.25. - [ ] **`GrowableBuffer::outgrow` and `SlotTable::sync` remake and refill a whole table on the frame the doubling trips** — `components/rtxvulkan/device/memory/growablebuffer.hpp:38-40`, `components/rtxvulkan/device/memory/growablebuffer.cpp:19-25`, `components/rtxvulkan/device/memory/slottable.hpp:99-103`, `components/rtxvulkan/device/memory/slottable.hpp:70`.
