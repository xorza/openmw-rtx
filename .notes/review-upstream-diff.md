# Review of the fork's diff against upstream

> **When you address an item, delete it.** Do not mark it done. The file lists open findings only.

Scope: every production file the fork adds or changes against upstream's merge base `46bd4599`, about 150k lines in 891 files. Tests and the APIs they use are out of scope. Seven reviewers read one area each. Every high finding, and the present-target finding, was then checked against the code a second time.

Severity: **high** is a wrong value, a crash, undefined behaviour, or a check that passes while broken. **medium** is an ownership, design or duplication problem with a real cost. **low** is a simplification, dead code, a name, or a comment that breaks the guide.

## 1. An index derived from something that moves, where a stable key was needed

- [ ] **high** — `components/rtxvulkan/scene/scenebuffers.cpp:303`, `:321` against `:238`–`:246` — A placement with no material gets `row.mMaterial = materials.size()`, which is the sentinel's index when the row is written. When the material table grows, `shade` moves the sentinel to the new end and writes a real material into the old index. Instance rows are rewritten only for new slots and for `changed` (`:334`, `:337`), so the placement keeps the old index. The walk makes such placements: `MaterialResolver::resolve` answers `sNoIndex` for an empty shading path (`mirror/materialresolver.cpp:252`), and `adopt` does for a reading with no key (`:229`). Consequence: the untextured surface is shaded as whichever material took the old slot. Fix: give the sentinel a fixed place that does not depend on the table's length (a reserved row, or a flag the hit tests). That also removes the full rewrite of the material table at every growth (`:241`–`:247`).
- [ ] **high** — `components/rtxvulkan/vulkanrenderer.cpp:560`, `components/rtxvulkan/trace/fogvolume.hpp:81`–`:86`, `components/rtxvulkan/framering.cpp:106`–`:119` — The fog volume writes `mScatter[traceSlot]` and reads the other half as the last frame's history. `traceSlot` is `mRing.getRecordingSlot()`, which is `mFrame % 2`, and `skipFrame` increments `mFrame` too (`framering.cpp:118`). The game skips a frame when the view has no basis (`apps/openmw/mwrender/rtx/rtxrenderer.cpp:815`–`:818`). Sequence: trace Z in slot 1, trace A in slot 0, skip in slot 1, trace C in slot 0. C discards A and reads Z as its history, while `mPreviousCamera` is still A's. The header comment claims this choice of slot prevents exactly that. Consequence: a wrong fog history on the frame after every skip. Fix: flip the fog's pair on each trace the chain records, as `TemporalTurns` does for the denoisers. `stepRipples` (`vulkanrenderer.cpp:582`) takes the same slot, so check it with the same fix.
- [ ] **low** — `components/rtx/scene/scenedesc.cpp:274`–`:277`, `components/rtx/scene/lightgrid.cpp:92` — `orderLights` sorts by position, but `rebuild` compares each lamp by its rank. A carried torch changes rank whenever its x passes another lamp's, and every lamp between the two ranks then compares against its neighbour's old entry, so the grid is filled again. The saving claimed at `lightgrid.cpp:84` fails for the lamp most likely to move. Fix: compare by a key that stays the same from frame to frame.
